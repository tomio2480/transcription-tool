# AMD GPU で Vulkan 版 whisper.cpp を使う判断と測定（2026-09-24）

## 概要

対象は NVIDIA GPU を持たない端末（Ryzen 9 7940HS，Radeon 780M）である．
この端末で，Vulkan 版の whisper.cpp を自前でビルドした．
`WHISPER_CLI_PATH` で指定して使う方式を採る．
Vulkan 版を使うためのコードと spec の変更は無い．
調査の過程で，異常終了時の終了コードを表示する修正（#7）も入れた．
`setup` への `vulkan` バリアント追加は見送った．

## 🧭 背景

- `setup` は `nvidia-smi` の有無で `cuda` / `cpu` を選ぶ．AMD GPU の端末では `cpu` になる．
- whisper.cpp v1.9.2 の公式リリースにある Windows 向け配布物は，CPU 版・BLAS 版・cuBLAS 版だけである．
  Vulkan 版と HIP 版は無い．v1.9.4 は 2026-09-24 時点で配布物が無い．
- 文字起こしの実行側は GPU 固有の引数を渡していない．
  GPU バックエンド付きでビルドした whisper-cli なら，差し替えるだけで GPU を使う．

## ⚖️ 検討した選択肢と判断

表 1 検討した選択肢．

| 選択肢 | 内容 | 判断 |
|---|---|---|
| 1 | Vulkan 版を自前ビルドし `WHISPER_CLI_PATH` で指定する | 採用 |
| 2 | `setup` に `vulkan` バリアントを追加する | 見送り |
| 3 | CPU 版のまま使う | 不採用（約 3 倍遅い） |

- 選択肢 1 は既存の要件 6（パスの解決順）の範囲に収まる．spec の変更を要しない．
- 選択肢 2 は，要件 5 の「固定タグの公式配布物を SHA256 で検証して配置する」前提と両立しない．
  上流に配布物が無いため，`setup` 中のビルドか自前配布が必要になる．
  いずれも spec の変更を伴う．
  上流が Vulkan 版の配布を始めたら再検討する．
- 端末固有のパスは Public の README に書かない．ユーザー環境変数に持たせる．
  エージェント向けの約束事は `AGENTS.md` に置き，利用側リポジトリから参照させる．

## 📏 測定結果

同じ 5 分の日本語録音（実録音の冒頭を切り出したもの）で，`transcribe-audio transcribe` の所要時間を測った．

表 2 構成別の所要時間．

| 構成 | 所要時間 | CPU 版との比 |
|---|---|---|
| CPU 版（v1.9.2 公式，既定 4 スレッド） | 270.7 秒 | 1.0 |
| Vulkan 版，ドライバー 2024-10 版，coopmat 無効 | 99.2 秒 | 2.7 倍速 |
| Vulkan 版，ドライバー 26.8.1，coopmat 無効 | 113.0 秒 | 2.4 倍速 |
| Vulkan 版，ドライバー 26.8.1，coopmat 有効 | 86.2 秒 | 3.1 倍速 |

- 62 分の録音全体は，Vulkan 版（26.8.1，coopmat 有効）で 1145.7 秒だった．録音長の 0.31 倍である．
  同じ行の連続などの幻覚の兆候は見られなかった．
- CPU 版と Vulkan 版の文字起こし結果は，`difflib.SequenceMatcher` の比で 0.996 だった．
  精度の差は実用上無視できる．
- 11 秒の短い合成音声では，CPU 版で 41 秒かかった．モデル読み込みが支配的になるため，短い録音の倍率は参考にならない．

## 🧱 詰まりどころ

- **ドライバー 2024-10 版での異常終了**: Vulkan 版は GPU 処理の開始直後に `0xC0000409` で落ちた．
  flash attention の無効化（`-nfa`）では直らなかった．
  `GGML_VK_DISABLE_COOPMAT=1` で回避できた．
  ドライバーを 26.8.1 へ更新すると，coopmat 有効のまま動いた．
- **並列ビルドの失敗**: `cmake --build -j 16` では Vulkan シェーダー生成が `MSB8066`（コード 4551）で失敗した．
  `-j 1` で通った．
- **パス長**: スクラッチ領域のような深いパスへの `git clone` は，`Filename too long` で checkout に失敗した．
  `%LOCALAPPDATA%\whisper-build` のような浅いパスへ置く．
- **証明書**: 初回の `setup` で，Hugging Face からのモデル取得が `CERTIFICATE_VERIFY_FAILED` で失敗した．
  直後の再実行では成功した．
  原因は，Windows がルート証明書を必要な時点で取得する挙動と推測する．
  確定はしていない．
- **ドライバー更新と実行の競合**: 文字起こしの実行中にドライバーを更新すると，処理は異常終了した．
  このときツールのエラーには whisper-cli の終了コードが含まれず，原因の切り分けに時間を要した．

## 🔭 今後の論点

- whisper.cpp の異常終了時に，終了コードをエラーメッセージへ含める（`transcribe.py`）．#7 で対応した．
- CPU 版は whisper-cli の既定の 4 スレッドで動いている．`-t` の指定で速くなる余地がある．未測定である．
- 上流が Vulkan 版の Windows バイナリを配布し始めたら，選択肢 2 を再検討する．
